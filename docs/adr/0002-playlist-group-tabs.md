# ADR-0002：「加到歌单」面板按音源分组，默认停在当前音源

日期：2026-11-27
状态：已确认

## 背景

「加到歌单」面板把本地歌单和各平台绑定歌单混在一个扁平列表里。用户常在每个平台各有一个大歌单（例如各平台的「我喜欢的音乐」），打开面板后要在一串几百上千首的歌单里找当前音源对应的那个。

面板需要一排分组 tab（全部 / 本地 / 各绑定平台），并且打开时默认停在「这首歌的音源」那一组。

难点在"这首歌的音源"怎么算：播放中可能被换源，尤其是自定义音源 `lx`。`lx` 只是一个取流通道，自己不拥有平台歌单。另外收藏写回平台已经有一条规则（`favoriteSourceSong`）：无论换成什么源取流，都写回歌曲原本所属的平台。如果面板照抄这条规则，普通换源后默认分组会停在"原始平台"而不是用户正在用的平台，和直觉相反。

## 决定

默认分组按以下顺序算（`defaultPlaylistGroup`）：

1. 不在播放的歌：用它自己的 `source`。
2. 正在播放的歌：用实际取流源（`currentSource.providerId`）。
3. 取流源是 `lx`：退回歌曲原本所属平台（`currentTrack.sources` 的主来源，即"切换前"那首）。
4. 取流源还没解析出来：按歌曲原本所属平台。

算出的候选分组不存在时先退「本地」，本地也没有未绑定歌单时落到「全部」（`resolvePlaylistGroup`），保证打开面板时总有一个合法的选中项。

分组 tab 复用歌单库的同一套组件和分组函数；只有一组歌单时不显示 tab。

## 后果

- 收藏写回平台与面板默认分组是两条规则：前者永远写回原平台，后者普通换源跟随取流源、只有 `lx` 才退回原平台。两条规则各有单测（`FavoriteSyncTest`、`PlaylistGroupingTest`），改动时不要合并成一条。
- `lx` 播放的歌如果本身就是脚本来源（没有原始平台版本），候选分组是 `lx`，按兜底落到「本地 / 全部」；这是可接受的降级，不新增"记住上一次音源"的持久状态。
- 面板每次打开重新计算默认分组，不记忆上次选中的 tab；"当前音源"变化时不会出现停在旧分组的情况。
- 新建歌单固定在 tab 下方、归「本地」组；新建后不自动切 tab，只靠面板提示条告知。
