# PC 原生密度体系（t15）

> 背景：上一版把 Android 平板的尺寸直接搬到桌面（行高 56dp、字号 16sp、大卡 248dp、内边距 32dp），
> 在 1440×900 的窗口里是「平板界面放大版」，被用户否决（原话「这tm是pc端？」）。
> 本文件定义 PC 的尺寸基准，并记录四页重做的取舍。

## 2. 四页重做要点

### 榜单页 `ChartsPage.kt`
- 轮播 400×248 → **320×180**：1440 窗口的内容区（扣掉 68dp 导航与 380dp 播放窗格）约 990dp，
  3 张 320dp 卡 + 间距刚好铺满，首屏还能看到下方两栏。
- 主推榜歌曲从「NO. 序号 + 52dp 封面双行」→ **32dp 单行**（序号/标题/歌手/时长/播放键），
  可见行数 8 → **18**。
- 更多榜单 150dp 胶囊两列 → **100dp 方块三列**。

### 歌单页 `PlaylistsPage.kt`
- 分类胶囊从横向滚动 → **FlowRow 换行铺满**（PC 窗口宽，藏起来的分类等于不可用）。
- 4 列固定网格 → **按内容区宽度自适应 5-8 列**（168dp 封面 + 8dp 间距），1440 窗口下 5 列 × 3 行 = 15 张。

### 搜索页 `SearchPage.kt`
- 加**列头**：序号 / 标题 / 歌手 / 专辑 / 来源 / 时长，点列头三态排序（升序 → 降序 → 默认）。
- 结果行 56dp 双行 → **32dp 单行**，一屏 9 条 → **20+ 条**。
- 来源从大胶囊 → **12sp 小标签**（`SourceTag`）。

### 我的 `LibraryPage.kt`
- 「4 个 96dp 统计卡 + 卡片流」→ **分组折叠列表**：
  `▾ 喜欢 (N)` / `▾ 最近播放 (N)` / `▸ 下载 (N)` / `▸ 自建歌单 (N)`，每组右侧数量，展开是 32dp 行。
- 「下载」「自建歌单」暂无数据源（本地库 Room 在 :core，桌面装配排 t2b 之后），分组保留 + 空态说明，不隐藏。

## 3. PC 交互（四页统一，实现在 `Metrics.kt`）

| 交互 | 实现 | 备注 |
| --- | --- | --- |
| 行 hover | `PcRow` 内置 `hoverable` + `animateColorAsState` | transparent → `surfaceContainerHigh`，100ms |
| 单击选中 | `RowSelection` | 选中行底色 `secondaryContainer` 55% |
| 双击播放 | `PcRow` 手势（400ms 内两次左键） | 单击不播放，避免误触 |
| Ctrl+单击 | 多选切换 | |
| Shift+单击 | 区间选择（以锚点行起止） | |
| 右键菜单 | `PcRow` 内 `DropdownMenu`（Press 时按光标定位） | 播放 / 下一首播放 / 加入歌单 / 查看歌手 / 喜欢 / 复制链接 |
| 卡片 hover | `Modifier.hoverLift`（1.02 缩放）+ 播放按钮浮层 | 轮播与歌单卡 |
| 滚轮 | LazyColumn/LazyRow 原生 | 无需代码 |

**如实降级（写在代码注释里）**：
- 「加入歌单」禁用：桌面还没有本地歌单库（Room 已落 :core，装配是 t2b 之后的事）。
- 「复制链接」：`Song.link` 还没经 `MusicCatalog` 暴露，复制 `provider:trackId`（可被链接解析复用），
  B3 换成真实平台链接。
- 播放页 / 歌词页 / 播放窗格 / 迷你条不在 t15 范围（audio2 的 t16），本轮的密度只覆盖四个浏览页。

### 已知问题（截图环境）

1. **搜索框内的输入文字在离屏渲染下是豆腐块**：`ImageComposeScene`（Skia 无窗口）里
   `BasicTextField` 走的是另一条字体排版路径，拿不到中文 fallback；同一页面的普通 `Text`
   正常（结果行标题都是中文）。**真实窗口不受影响**（普通 Text 与 TextField 都用系统字体回退）。
   也已尝试显式 `TextStyle`（不继承 typography），无效——属 Compose Desktop 离屏渲染的限制。
   截图中查询词以「「晴天」· 4 条结果」为准。
2. **搜索只有 4 条结果**：默认平台 netease 的搜索接口在本机常返回 502，截图场景切到 QQ 音乐；
   QQ 对「晴天」实际只回 4 条（含翻唱），不是界面截断。
3. **「下载」「自建歌单」为空**：本地库（Room）在 :core 已就绪，桌面装配排在 t2b 之后；
   分组保留 + 空态说明，不隐藏。

## 5. 与 Android 平板的差异（PC 化取舍与理由）

| 平板做法 | PC 做法 | 为什么 |
| --- | --- | --- |
| 行高 56dp（触摸最小可点高度） | 32dp | 鼠标指针精度远高于手指，48dp 起是触摸的硬要求，PC 上纯属浪费 |
| 字号 16sp（远距离可读） | 13sp | 桌面观看距离 50-70cm，比手持更近；13sp ≈ 平板上 16sp 的观感 |
| 4 列 148dp 卡 | 5-8 列 168dp 卡（自适应） | 窗口宽度不是常量，按宽度算列数才不会在宽屏上留大片空白 |
| 横向滚动装分类 | FlowRow 换行 | 桌面用滚轮横向滚动是反直觉的；分类本来就该一次看全 |
| 大卡 400×248 轮播 | 320×180 | 首屏的信息优先级：轮播只是入口，歌曲列表才是主体 |
| 单击即播放（触摸没有 hover/右键） | 单击选中、双击播放、右键菜单 | PC 的标准语义；误触代价高 |
| 卡片阴影 + 大圆角 | 抬升 1.02 + 10dp 圆角 | 高密度下重阴影会糊成一片 |
| 统计大卡 96dp（4 个） | 折叠分组行（32dp） | 数字是次要信息，占满一屏不如直接看列表 |
